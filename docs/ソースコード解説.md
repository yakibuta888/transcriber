## 1. はじめに - このツールは何をするのか

このツールは「音声ファイルを文字に起こす」ためのアプリケーションです。

**できること：**
- 音声ファイル（会議の録音など）を読み込む
- 音声からノイズ（雑音）を取り除いてクリアにする
- AIが音声を聞き取って文字に変換する
- 誰が話しているかを自動で判定する（話者分離）
- 結果をテキストファイルに保存する

**使い方は2種類：**
- **GUI版**：画面でボタンをクリックして操作（開発途中。ローカルで動くが、Linuxサーバに未対応。）
- **CLI版**：コマンド（命令文）を打ち込んで操作（ユーザはapptainerを利用するシェルスクリプトを通して利用すること）

## 2. 全体の処理の流れ

音声ファイルが文字になるまでの流れを説明します。

```
【入力】音声ファイル
    ↓
【下準備】音声の前処理（6段階）
    ├─ 1. 音声の読み込み・形式変換
    ├─ 2. 一定のノイズ（エアコン音など）を除去
    ├─ 3. 音量の均一化
    ├─ 4. 突発的なノイズ（咳など）を除去
    ├─ 5. 声をクリアにする処理
    └─ 6. 最終的な音量調整
    ↓
【分析】AI による分析（並行処理）
    ├─ 文字起こし（音声→文字）
    └─ 話者分離（誰が話しているか）[オプション]
    ↓
【統合】結果の統合(話者分離を行う時のみ)
    ↓
【完成】テキストファイル出力
```

## 6. 音声処理の仕組み

### 6.1 前処理サービス - `backend/src/domain/services/pre_processing_service.py`

**役割：** 音声をAIが認識しやすい状態に整えます。音声信号の正規化、ノイズ除去、音質向上などの前処理を行います。

**処理の流れ（6ステップ）：**

#### Step 1: 音声ファイルの読み込み（30行目〜）
```python
raw_audio = AudioLoader.load(path)
```
- 音声ファイルを読み込む
- 16kHz（1秒間に16,000回サンプリング）に変換
- ステレオ（左右2チャンネル）をモノラル（1チャンネル）に変換

**なぜ必要？** AIモデルは特定の形式の音声しか処理できないため、統一した形式に変換します。

#### Step 2: 定常ノイズの除去（42行目〜）
```python
clean_audio = self._stationary_processor.reduce_stationary_noise(raw_audio.waveform)
```
- 常に鳴っているノイズを除去
- 例：エアコンの音、パソコンのファン音、ホワイトノイズ

**なぜ必要？** 一定の背景音があると、声が聞き取りにくくなるためです。

#### Step 3: ピーク正規化（54行目〜）
```python
normalized_audio = AudioNormalizer.peak_normalize(clean_audio)
```
- 音量を一定の基準に揃える
- 大きすぎる音を抑え、小さすぎる音を上げる

**なぜ必要？** 音量がバラバラだと、AIが正しく認識できないためです。

#### Step 4: 非定常ノイズの除去（66行目〜）
```python
denoised_audio = self._transient_processor.reduce(normalized_audio)
```
- 突発的なノイズを除去
- 例：咳、くしゃみ、物を落とす音
- DeepFilterNet（ディープフィルターネット）というAIを使用

**なぜ必要？** 突然の大きな音は、文字起こしの精度を大きく下げるためです。

#### Step 5: ボーカルエンハンスメント（78行目〜）
```python
enhanced_audio = self._enhancer.enhance(denoised_audio)
```
- 声をよりクリアにする
- 低音域を1.1倍、高音域を1.4倍に強調
- 音声を圧縮して聞き取りやすくする

**なぜ必要？** 人の声の帯域を強調することで、認識精度が上がるためです。

#### Step 6: 再正規化（90行目〜）
```python
re_normalized_audio = AudioNormalizer.peak_normalize(enhanced_audio)
```
- 最終的な音量調整
- 前の処理で変わった音量を再度揃える

### 7.2 Whisper Large v3 - `backend/src/domain/services/large_service.py`

**特徴：**
- OpenAI社が開発した多言語対応モデル
- 高精度だが処理時間が長い
- 日本語以外の言語にも対応

**処理の流れ（55行目〜）：**

```python
def run(self, option_args, progress):
    # 1. 音声の前処理
    audio_entity = pre_processing_service.process(self.audio_file, progress)

    # 2. 並列処理（同時に2つの作業を実行）
    with ThreadPoolExecutor(max_workers=2) as executor:
        # 文字起こし作業
        future_asr = executor.submit(asr_task)
        # 話者分離作業
        future_diar = executor.submit(diar_task)
```

**ポイント：**
- 音声を「チャンク」（小さな塊）に分割して処理
- チャンク長は5〜180秒（初期値15秒）※チャンクが長いと途中で切れるため、15秒推奨
- 文字起こしと話者分離を同時に実行して時間短縮

**チャンク処理のイメージ：**
```
60秒の音声 → [0-15秒][15-30秒][30-45秒][45-60秒] → 各チャンクを処理 → 結果を結合
```

## 8. 話者分離（誰が話しているかの判定）

### 8.1 話者分離器 - `backend/src/domain/logics/speaker_diarizer.py`

**役割：** 音声の中で「誰が」「いつ」話しているかを判定します。

**使用技術：** pyannote（パイアノート）- フランスの研究機関が開発したAI

```python
class SpeakerDiarizer:
    def __init__(self, model, hf_token):
        # 話者分離AIを読み込む
        self.pipeline = DiarizationPipeline.from_pretrained(model, ...)

    def get_segments(self, audio, num_speakers, ...):
        # 話者分離を実行
        diarization = self.pipeline(audio, **diarization_args)

        # 結果を整理
        for segment, _, speaker in diarization.itertracks(yield_label=True):
            segments.append({
                "start": segment.start,    # 開始時間
                "end": segment.end,        # 終了時間
                "speaker": speaker         # 話者名（SPEAKER_00など）
            })
```

**オプション：**
- `num_speakers`：話者数がわかっている場合に指定（精度向上）
- `min_speakers`：話者数の下限
- `max_speakers`：話者数の上限

### 8.2 結果の統合 - `backend/src/domain/logics/merger.py`

**役割：** 文字起こし結果と話者分離結果を組み合わせます。

**処理の仕組み：**

```python
class ResultMerger:
    @staticmethod
    def merge(asr_chunks, diar_segments, progress):
        for chunk in asr_chunks:
            # 各文字起こし結果に対して、
            # 最も重なりが大きい話者区間を探す
            max_overlap = 0
            for seg in diar_segments:
                overlap = 重なり時間を計算
                if overlap > max_overlap:
                    assigned_speaker = seg["speaker"]

            # 結果を格納
            merged.append({
                "speaker": assigned_speaker,
                "text": chunk["text"],
                "start": ws_start,
                "end": ws_end
            })
```

**アルゴリズム：**
各文字起こしチャンクに対して、話者分離で得られた全ての話者区間との時間的重なり（オーバーラップ）を計算します。最も重なりが大きい話者区間の話者を、そのチャンクの話者として割り当てます。これにより、時系列データ同士を時間軸で照合し、統合します。

## 9. モデルのローカル保存とオフライン動作

このツールは、AIモデルをすべてローカルに保存し、インターネット接続なしで完全オフライン動作します。

### 9.1 概要と方針

**オフライン動作の実装方針：**
- **本番環境**：完全オフライン動作（インターネット接続不要）
- **開発環境**：オンラインフォールバックあり（検証・緊急用）
- **総容量**：約53GB のモデルファイル

### 9.3 パス解決の中核：get_models_dir.py

**ファイル：** [backend/src/domain/common/get_models_dir.py](backend/src/domain/common/get_models_dir.py)

**役割：**
すべてのモデルのローカルパスを一元的に解決します。このファイルがパス管理の中心となっています。

**実装：**
```python
def get_models_path(folder_name: str) -> str:
    if getattr(sys, 'frozen', False):
        # exe化後: 実行ファイルのあるディレクトリ
        base_dir = os.path.dirname(sys.executable)
    else:
        # 開発時: srcを基準にする
        base_dir = os.path.abspath(
            os.path.join(os.path.dirname(__file__), '..', '..')
        )
    model_path = os.path.join(base_dir, 'models', folder_name)
    model_path = Path(model_path).resolve()
    if not model_path.exists():
        raise FileNotFoundError(f"Models directory does not exist: {model_path}")

    return model_path.as_posix()
```

**動作：**
- 開発時：`backend/src/` を基準に `models/{folder_name}` を解決
- exe化後：実行ファイルのディレクトリを基準に解決 ※GUI版をexe配布する話が出たときの残骸
- モデルが存在しない場合：`FileNotFoundError` を発生させる

## 10. 結果の出力

### 10.1 出力処理 - `backend/src/domain/common/output.py`

**役割：** 文字起こし結果をテキストファイルに保存します。

```python
def write_text_file(outdir, outname, contents):
    # 出力ファイルのパスを作成
    outfile = os.path.join(outdir, f"{outname}.txt")

    # 開始時間でソート
    contents.sort(key=lambda x: x["start"])

    # ファイルに書き込み
    with open(outfile, "w", encoding="utf-8") as f:
        for item in contents:
            f.write(f"[{start:.2f} - {end:.2f}] {speaker}: {text}\n")
```

**出力形式：**
```
[0.50 - 2.30] SPEAKER_00: こんにちは、本日の会議を始めます。
[2.50 - 5.80] SPEAKER_01: はい、よろしくお願いします。
[6.00 - 10.20] SPEAKER_00: まず、前回の議事録の確認からです。
```

**形式の説明：**
- `[0.50 - 2.30]`：発話の開始時間と終了時間（秒）
- `SPEAKER_00`：話者の識別子
- その後に発話内容

## 11. スクリプトの解説

### 11.1 Apptainerスクリプト - `script/apptainer.sh`

**役割：** Apptainer（アプテイナー）というコンテナ技術を使って、文字起こしを実行します。

**Apptainerとは？**
Singularityの後継となるコンテナランタイムで、特にHPC（高性能コンピューティング）環境で広く使われています。rootless実行（管理者権限不要）をサポートしており、セキュリティ要件の厳しい環境でも利用可能です。

**使い方：**
```bash
./script/apptainer.sh <作業ディレクトリ> <モデル名> <音声ファイル> <出力名> [diarize]
```

**例：**
```bash
./script/apptainer.sh mywork whisper-large-v3 meeting.wav result diarize
```

**スクリプトの処理内容：**

```bash
# 1. 引数のチェック
if [ "$#" -lt 4 ]; then
  echo "使い方: $0 <ディレクトリ名> <model名> <音声ファイル名> <出力名> [diarize]"
  exit 1
fi

# 2. 変数の設定
WORKDIR="$1"
MODEL="$2"
AUDIOFILE="$3"
OUTNAME="$4"
SHARED_DIR="/mnt/data/$WORKDIR"

# 3. キャッシュディレクトリの準備
export APPTAINER_CACHEDIR="$SHARED_DIR/apptainer_cache"
export APPTAINER_TMPDIR="$SHARED_DIR/tmp"

# 4. Apptainerで実行
apptainer exec --nv \                    # GPUを使用
  --bind "$SHARED_DIR:/files" \          # フォルダをマウント
  /mnt/data/container/transcriber.sif \  # コンテナイメージ
  python src/cui/main_cui.py ...         # 実行コマンド
```

**重要なオプション：**
- `--nv`：GPUを使用する
- `--bind`：ホストのフォルダをコンテナ内にマウント
- `--contain`：ホストの環境を隔離
